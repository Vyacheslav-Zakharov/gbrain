# Portal: эксплуатационная приёмка

Дата запуска приёмки: 2026-07-20

Контур: `https://gbrain.avb.kz/portal`

Версия Portal: embedded React/Vite SPA из private `source-ingest/master`.

## Цель

Проверить не только техническую работоспособность, но и то, что сотрудник без инструктажа может найти и прочитать нужный документ, не нарушая границы доступа.

## Baseline на 2026-07-20

- `gbrain-persistent.service`: active, текущий процесс без автоматических рестартов.
- Local/public health: `ok`, engine `postgres`, installed version `0.42.52.0`.
- Неавторизованный `/portal` перенаправляет на `/login`.
- `/portal-legacy` отвечает `410`.
- Update-guard: 83 файла, checksum errors = 0.
- Server-side Portal session store: mode `0600`, одна активная запись.
- После deployment были три предупреждения service failure 2026-07-16 во время controlled rollout; после текущего запуска 2026-07-18 новых warning/alert записей не обнаружено.

Одна session-запись не доказывает регулярное использование. До moderated pilot нельзя считать пользовательскую приёмку завершённой.

## Состав пилота

5–7 сотрудников с разными формами доступа:

- 2 пользователя с широким корпоративным read-доступом;
- 2–3 пользователя с ограниченным departmental read-доступом;
- 1–2 пользователя преимущественно с телефона;
- минимум один пользователь, который не знает структуру источников.

Не включать в отчёт email, названия закрытых источников или тексты закрытых документов. Идентификатор участника: `U01`…`U07`.

## Сценарии

### S1 — известное местоположение

Задание: выбрать разрешённый источник, пройти по дереву и открыть заранее выбранный документ.

Критерии:

- документ открыт не более чем за 30 секунд;
- после выбора источника не более 3 осмысленных действий;
- пользователь понимает, где находится в дереве;
- запрещённые источники не видны.

### S2 — поиск

Задание: открыть `Ctrl/Cmd+K` или кнопку поиска, найти документ по названию/фразе и открыть результат.

Критерии:

- документ открыт не более чем за 30 секунд;
- snippet помогает отличить результаты;
- стрелки + Enter работают для keyboard-пользователя;
- поиск не показывает названия или fragments недоступных источников.

### S3 — чтение и связи

Задание: открыть длинную Markdown-страницу, воспользоваться оглавлением, перейти по wikilink/backlink и вернуться Back.

Критерии:

- заголовки, таблицы, код и длинные строки читаемы;
- переход открывает ожидаемый документ;
- Back возвращает к исходному документу;
- restricted target возвращает безопасное not-found состояние без раскрытия источника.

### S4 — телефон

Задание: на ширине около 390 px открыть explorer drawer, выбрать документ, закрыть drawer и открыть context drawer.

Критерии:

- отсутствует горизонтальный overflow страницы;
- touch targets не меньше 44 px;
- reader занимает доступную ширину;
- drawer закрывается по overlay/Escape и возвращает фокус.

| Поле | Значение |
|---|---|
| Участник | U01…U07 |
| Устройство | desktop / tablet / phone |
| Форма доступа | broad / restricted |
| Сценарий | S1 / S2 / S3 / S4 |
| Успех без подсказки | да / нет |

| Severity | P0 / P1 / P2 / observation |

## Правила severity

- **P0:** утечка ACL, обход auth, XSS/active content, потеря доступности Portal.
- **P1:** базовый сценарий нельзя завершить без помощи или на одном из основных viewport.
- **P2:** сценарий завершается, но заметно медленнее/непонятнее целевого.
- **Observation:** субъективное пожелание без доказанного влияния на задачу.

## Gate завершения пилота

Пилот считается пройденным, если одновременно:

- минимум 5 участников выполнили S1–S3;
- минимум 2 участника выполнили S4 на телефоне;
- успешность без подсказки ≥ 85%;
- медиана S1 и S2 ≤ 30 секунд;
- P0 = 0;
- открытые P1 имеют owner и решение;
- restricted-account negative paths проверены минимум одним участником/оператором.
